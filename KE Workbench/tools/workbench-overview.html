Naming conventions

ArtifactElementConventionExample
VocabularyTermPreferred label in sentence case; synonyms as alternative labels"Pay period" (alternative: "Payroll cycle")
TaxonomyConceptUpperCamelCase identifier; preferred label in sentence case; codes in skos:notationWagesAndHours, label "Wages and hours"
OntologyClassUpperCamelCase singular nounPayrollRun, WorksiteEmployee
OntologyObject propertylowerCamelCase verb phraseperformedBy, governedBy
OntologyData propertylowerCamelCase noun phrase with has- or is- prefixhasEffectiveDate, isExempt

No acronyms in identifiers or preferred labels. Write ProfessionalEmployerOrganization, not PEO. Acronyms are recorded only as skos:altLabel so search still finds them, and a new acronym is added to Appendix F before it appears in any label.

URI conventions

URIs are persistent, readable and never reused. Namespaces are slash-based so each term resolves on its own; multi-word domain names are lower case and hyphenated (service-model).

Model Manager classifies graphs by these rules: a compliant base URL plus a kind in the path (vocabulary, taxonomy, ontology). Anything else lands under Other as a clean-up list. Compliant base URLs are a workbench setting, so the legacy enablingvalue.com host keeps working while assets migrate.

Required before Draft → Candidate

  • IRI under the base URL; UpperCamelCase, no acronyms, no hierarchy in the path
  • Label — rdfs:label and skos:prefLabel, one per language, @en, sentence case, full words
  • Is defined by — rdfs:isDefinedBy the owning ontology
  • Definition — skos:definition, one sentence, genus plus differentia (ISO 704): "A [parent] that [distinguishing feature]"
  • Sub-class of — at least one named parent; the hierarchy carries the meaning
  • Governance — lifecycle status, owl:versionInfo, created, modified, creator

Recommended and restricted

  • Recommended: skos:scopeNote (what is in and out), skos:example
  • As needed: skos:altLabel for synonyms, acronyms, legacy and persona terms (3.8)
  • Codes: skos:notation is the only place a code or acronym may stand alone
  • Restrictions: existential (someValuesFrom) only
  • Avoid: owl:equivalentClass without Architecture approval; owl:disjointUnionOf
  • Closed sets only: owl:oneOf, for example a lifecycle status
sm:DocumentationStandards a owl:Class ; rdfs:label "Documentation standards"@en ; skos:prefLabel "Documentation standards"@en ; skos:altLabel "Documentation guidelines"@en ; skos:definition "A software engineering artifact that specifies the required content, structure, format, review, and retention of the documentation produced during development."@en ; rdfs:isDefinedBy <https://www.insperity.com/ontology/service-model/> ; rdfs:subClassOf sm:SoftwareEngineeringArtifact ; core:hasLifecycleStatus core:Draft ; owl:versionInfo "0.1.0" .

Lifecycle

Draft→Candidate→Released→Deprecated→Retired

Released versions are immutable. Deprecated versions carry a sunset date; terms are deprecated, never deleted.

Semantic versioning

BumpWhenIn the workbench
MAJORBreaks consumers — removes or redefines a class or propertyDeclared in the change record
MINORAdditionsDeclared in the change record
PATCHLabel and documentation fixesMetadata editors bump PATCH on save; a new asset starts at 0.1.0
  • Only ontology and vocabulary releases get versioned IRIs (owl:versionIRI, owl:priorVersion).
  • Class, property and concept IRIs never contain a version; a changed meaning means deprecate and replace.
  • Change records live in the append-only graph https://www.insperity.com/graph/change-log, one record per change set, linked by PROV-O.

Four design principles

  • Small core ontology owned by Architecture, aligned to BFO (ISO/IEC 21838-2). Domains extend the core, never the reverse.
  • Process step as anchor. Every fact attaches to the step that creates, uses or governs it: performedBy, consumes/produces, triggers, governedBy, measuredBy, precedes.
  • Domain ontologies specialize core classes; intra-domain properties stay inside the domain.
  • Operational modules hold inter-domain edges, so no domain imports another; domains align through reviewed SKOS bridges to the core.
