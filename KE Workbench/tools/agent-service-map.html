How the agents run in Copilot

Copilot and Copilot Studio reach the Sales Advisor only through the Keel Gateway, an MCP server that checks every call against the SSOT. Hosted agents run on Microsoft Agent Framework with Foundry models, triggered by CloudEvents or by a Copilot agent's run tool.

Agent families

Each family is an event chain: an agent's emitted event triggers the next. Select a family to filter the agent list.

Every operation is a tool on the Keel Gateway. Changing a tool's parameters is a breaking change for every Copilot package that pins it, so the editor lists the agents and packages affected before you submit.

Copilot packages

One Microsoft 365 Agents Toolkit project per agent that people talk to: a declarative agent (schema v1.8) whose only action is the Keel Gateway as a remote MCP server (plugin schema v2.4), pinned to that agent's tools and authenticated with Entra ID. The same agents can be built in Copilot Studio from the guides in the download.

Deploy

  1. Deploy the Keel Gateway with KEEL_AUTH=entra and register it in Entra ID with the SalesAdvisor.User app role.
  2. Register the gateway as an OAuth client in Teams Developer Portal; put the registration ID in each project's env/.env.dev as MCP_DA_AUTH_ID, with KEEL_GATEWAY_MCP_URL.
  3. Open each project in VS Code with the Microsoft 365 Agents Toolkit and run Provision; run the evaluations in evals/prompts.json; publish to the tenant catalog.
  4. Deploy the agents host with your Foundry project endpoint and model deployments; set KEEL_AGENTS_HOST_URL on the gateway.
Agents, tools and governance rules come from the PEO Sales Advisor design, the Decision Question Baseline (breaker tiers and integrity signals) and the SSOT register. Generated code targets Microsoft 365 declarative agent schema v1.8, plugin manifest v2.4 with a remote MCP server, Microsoft 365 Agents Toolkit v1.13 project files, Microsoft Agent Framework with Foundry models, and the Python MCP SDK 2.x.
